# Безопасность и Производительность

В **CodeContext** требования безопасности и скорости зафиксированы как исполняемые тесты (`dhat`, `divan`, `proptest`), которые запускаются в CI.

---

## 1. Инжиниринг производительности (Бюджет < 1 сек на 4 МБ)

### 1.1. Двухфазное сканирование (`Index` -> `Hydrate`)
1. **Фаза 1 (Индексация дерева):** Параллельный обходчик `ignore::WalkParallel` (`crates/scanner/src/discovery/parallel_walker.rs`) проходит дерево проекта во всех потоках CPU, отсекает `.gitignore`, проверяет первые 8 КБ файла через `memchr` на наличие `NUL`-байта (`binary_detector.rs`) и возвращает список `ScannedFile` с точными размерами файлов.
2. **Фаза 2 (Сборка с преаллокацией):** Зная точную сумму байтов всех выбранных файлов и размер маркеров шаблона, `IgnoreFileScanner` вычисляет итоговую ёмкость буфера заранее и пишет напрямую в преаллоцированный `String` (включая потоковую минификацию и AVX2-нормализацию `CRLF -> LF` без промежуточных аллокаций).

### 1.2. Доказательство ровно 1 аллокации кучи (`dhat`)
В файле `crates/scanner/tests/heap_allocations.rs` подключён глобальный профайлер аллокаций `dhat::Alloc`:
* `stats.total_blocks == 1` — в куче происходит **ровно одна аллокация** (0 реаллокаций при росте строки).
* `stats.total_bytes == expected_capacity` — выделяется с точностью до байта ровно столько памяти, сколько рассчитано заранее.

## 2. Архитектура безопасности

### 2.1. Песочница путей (`crates/apply/src/safety/sandbox.rs`)
Перед созданием или перезаписью любого файла из ответа ИИ путь проходит строгую нормализацию и проверку:
* Блокируются пустые пути и пути с `NUL`-символом (`\0`).
* Блокируются абсолютные пути (`/etc/passwd`, `\Windows\System32`).
* Блокируются префиксы дисков Windows, UNC-пути и альтернативные потоки данных NTFS (`C:`, `\\?\`, `file.txt:secret`).
* Блокируются любые компоненты родительской директории (`Component::ParentDir` / `..`).
