# Единый язык (Ubiquitous Language)

Согласно **Главе 2 книги «Learning Domain-Driven Design»**, Единый язык — это словарь предметной области, который одинаково используется в беседах, спецификациях, UI, тестах и именах типов в исходном коде Rust. В нём **запрещены двусмысленные термины и синонимы**.

---

## 1. Общие понятия и Окружение

| Термин в коде (Rust) | Термин (RU) | Строгое определение в домене |
| :--- | :--- | :--- |
| `Project` | **Проект** | Корневая директория исходного кода разработчика (`project_root`), над которой выполняются операции упаковки или патчинга. |
| `Anomaly` | **Аномалия** | Нештатная, но не фатальная ситуация при обходе проекта или разборе ответа (например, превышение глубины 32 уровней, файл > 1 МБ или оборванный блок кода), требующая предупреждения пользователя. |
| `CancelToken` | **Токен отмены** | Сигнал кооперативной остановки фонового обхода при изменении пользователем правил фильтрации в реальном времени. |

---

## 2. Поддомен упаковки контекста (`packing`)

| Термин в коде (Rust) | Термин (RU) | Строгое определение в домене |
| :--- | :--- | :--- |
| `FileEntry` | **Узел файла** | Метаданные обнаруженного файла в дереве проекта (относительный путь, размер в байтах, тип `FileKind`, статус выбора чекбоксом). Не хранит сам текст файла в памяти. |
| `SecretGuard` | **Защитник секретов** | Доменный фильтр безопасности, блокирующий попадание чувствительных файлов (`.env*`, `*.pem`, ключей SSH) в буфер обмена по умолчанию. |
| `PackResult` | **Результат упаковки** | Итоговая проекция (Read Model) собранного контекста: готовые сегменты текста, общий объём в байтах, число файлов и список обнаруженных аномалий. |
| `PackChunk` | **Сегмент буфера** | Неделимая часть упакованного контекста (по умолчанию 1 сегмент на весь проект, либо один из $N$ томов при включённой разбивке для браузера). |

---

## 3. Поддомен пресетов и шаблонов (`preset`)

| Термин в коде (Rust) | Термин (RU) | Строгое определение в домене |
| :--- | :--- | :--- |
| `Preset` | **Пресет (Профиль)** | Именованный набор правил отбора (`include`/`exclude` глобы, лимиты размеров, флаги минификации), который может храниться глобально или в `.ctxpack.json` проекта. |
| `OutputTemplate` | **Шаблон вывода** | Правила оформления текста для ИИ-чата: формат шапки с деревом проекта, разделитель `=== FILE: <path> ===` и закрывающий маркер. |

---

## 4. Поддомен применения изменений (`applying`)

| Термин в коде (Rust) | Термин (RU) | Строгое определение в домене |
| :--- | :--- | :--- |
| `ApplyPlan` | **План применения** | Корень агрегата, содержащий проверенный список операций над файлами (`FileOperation`), полученных после парсинга ответа ИИ. |
| `FileOperation` | **Файловая операция** | Конкретное действие над файлом в плане: полная перезапись (`WriteFull`), точечная замена (`SearchReplace`), наложение патча (`UnifiedDiff`) или удаление (`Delete`). |
| `Autofix` | **Автофикс** | Детерминированный алгоритм (без ИИ), восстанавливающий синтаксическую целостность оборванного или замусоренного ответа чата перед предпросмотром. |
| `Sandbox` | **Песочница** | Механизм принудительного удержания всех операций записи строго внутри `project_root` (защита от Path Traversal `..` и симлинк-атак). |
| `BackupManifest` | **Манифест бэкапа** | Журнал транзакции в `.ctxpack/backups/<timestamp>/manifest.json`, фиксирующий контрольные суммы изменённых и список вновь созданных файлов для выполнения **Undo**. |
