# Архитектура подсистемы плагинов и Жизненный цикл (Extension Host)

Подсистема расширений **CodeContext** спроектирована по образцу **VS Code / Zed / Raycast**, позволяя сторонним разработчикам добавлять в приложение новые экраны, провайдеры контекста, AST-компрессоры и команды палитры `Ctrl+P`, сохраняя холодный старт `< 10 мс`.

---

## 1. Жизненный цикл плагина

```text
[1. Discovery]       Чтение ~/.config/CodeContext/plugins/*/plugin.json (< 0.5 мс)
       │
       ▼
[2. Contributions]   Регистрация команд в Ctrl+P, вкладок и тумблеров без запуска кода
       │
       ▼
[3. Activation]      Срабатывание ActivationEvent (OnPackContext / OnCommand / OnView)
       │
       ▼
[4. Execution]       Вызов JSON-RPC 2.0 (stdin/stdout) или встроенного обработчика
```

---

## 2. Матрица разрешений (`PluginPermission`)

Плагины работают по принципу **Zero-Trust** и обязаны декларировать запрашиваемые права в `plugin.json`:

| Разрешение | Назначение | Инвариант безопасности ядра `core` |
| :--- | :--- | :--- |
| `workspace_selection` | Чтение списка файлов и управление чекбоксами дерева | Заблокированные `SecretGuard` узлы остаются неизменяемыми |
| `fs_read_project` | Чтение текстовых файлов внутри проекта | Проверяется через `validate_sandbox_path` и `SecretGuard` |
| `fs_propose_patch` | Формирование плана изменений `ApplyPlan` | Запись только через превью `DiffView` и бэкап `.ctxpack/backups` |
| `clipboard_access` | Доступ к системному буферу обмена | Только по явному действию пользователя |
| `terminal_propose` | Предложение терминальной команды | Требует подтверждения пользователя в нижней док-панели |
| `network_outbound` | Доступ к внешним API (Jira, GitHub, БД) | Отключено по умолчанию |
