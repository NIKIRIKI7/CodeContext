# Описание проекта: «Context Packer» (рабочее название)

## 1. Суть и цель

Кроссплатформенное десктоп-приложение на **Rust + GPUI** для разработчиков, которые работают с бесплатными веб-чатами ИИ (AI Studio и аналоги) без платных API/подписок. Две функции:

- **A. Упаковка контекста:** быстро отобрать файлы кодовой базы по настраиваемым правилам, отформатировать по настраиваемому шаблону и скопировать в буфер обмена для вставки в чат.
- **B. Применение изменений без ИИ:** принять ответ чата, распарсить его, показать предпросмотр/diff и безопасно применить к файлам проекта.

Ключевой принцип: **никакого встроенного ИИ** — только детерминированная обработка текста.

## 2. Пользователи и роли

Разработчики (в первую очередь — вы и коллеги), работающие на Windows/macOS/Linux. Потребности: минимум действий, гибкая настройка отбора, предсказуемость, безопасность (секреты, песочница), открытый исходный код.

## 3. Критерии успеха

- Кодовая база объёмом ~1M токенов (**≈3–4 МБ текста**) копируется в буфер **< 1 сек** (без учёта вставки в браузер).
- Отбор и упаковка запускаются из **контекстного меню Проводника/Finder** или из UI за 1–2 действия.
- Ни один секрет/игнорируемый артефакт не попадает в буфер без явного включения.
- Применение ответа ИИ не теряет данные (бэкап/undo) и не выходит за рамки проекта по умолчанию.
- Кроссплатформенность, установщик с автообновлением и самоинсталляцией.

## 4. Пользовательские сценарии

**Сценарий A1 (быстрый):** ПКМ по папке проекта в Проводнике → «Context Packer: Copy» → подхватывается активный пресет → в буфере готовый контекст → вставка в чат.

**Сценарий A2 (тонкий):** Открыть окно приложения → выбрать корень → дерево файлов с чекбоксами → настроить include/exclude/шаблон → предпросмотр + размер → «Копировать».

**Сценарий A3 (пресеты):** Переключение между профилями под разные задачи/проекты; импорт/экспорт пресета файлом; пресет может лежать в корне проекта и шариться через git.

**Сценарий B1:** Скопировать ответ чата → вставить в окно «Применить» (или, при включённой настройке, приложение само читает буфер) → предпросмотр (опц. diff) → применить → бэкап сохранён в `.ctxpack/backups/<ts>/`.

**Сценарий B2 (битый ответ):** Приложение сообщает о проблеме (незакрытый маркер, висящий путь, обрыв) → кнопка «Автофикс» → детерминированное восстановление → повторный предпросмотр.

## 5. Функциональные требования

### 5.1 Модуль A — упаковка контекста

**Отбор файлов**

- Учитывать `.gitignore` проекта (и вложенные).
- Пресеты с настраиваемыми правилами include/exclude (glob), whitelist/blacklist — на усмотрение пользователя.
- По умолчанию игнорировать тяжёлые папки: `node_modules`, `target`, `.git`, `dist`, `build` и т.п. — включаемы вручную.
- По умолчанию скрывать секреты (`.env*`, `*.pem`, `*secret*`, `id_rsa*` и т.п.) с предупреждением в UI; включение — только явно в настройках.
- Бинарные/нетекстовые файлы — определять эвристикой (NUL-байты + расширение) и исключать по умолчанию.
- Крупные файлы — включать, но показывать предупреждение (порог настраиваемый).
- Симлинки — **по умолчанию пропускать**, следование — опция с защитой от циклов.
- Предупреждение при аномалиях обхода: **глубина > 32** или **> 50 000 файлов** (пороги настраиваемые).

**Форматирование вывода**

- Полностью настраиваемый шаблон: шапка (опц. дерево проекта), разделитель, маркер пути, блок содержимого, финал.
- Дефолт: **полные файлы с явной пометкой пути** (формат совместим с AI Studio).
- Порядок файлов — настраиваемый; по умолчанию не критичен (алфавит по пути).
- Сжатие (удаление комментариев/пустых строк, схлопывание отступов) — **по умолчанию выключено**, настраивается.
- Кодировки/переводы строк — сохранять как в оригинале.

**Буфер и UI**

- Копирование в буфер как plain text (HTML/rich — опция).
- Живой предпросмотр итогового текста + **размер в КБ/МБ** (оценка токенов не требуется).
- Главное окно (всё в MVP): выбор корня, дерево с чекбоксами, редактор правил/пресетов, предпросмотр, «Копировать», вкладка «Применить».
- Глобальный хоткей; интеграция с Проводником/Finder/файловыми менеджерами Linux.

**Интеграция с ОС**

- Windows: регистрация команд в контекстном меню (`Directory`, `Directory\Background`, `*`) через реестр — без COM на первом этапе; передача путей в запущенный инстанс (single-instance + IPC).
- macOS: Services / Finder Sync Extension.
- Linux: `.desktop`-actions (Nautilus/Nemo/Dolphin — по покрытию).
- Абстрактный слой `shell_integration` с нативными бэкендами.

### 5.2 Модуль B — применение изменений (этап 2, архитектурно закладывается сразу)

- Ввод: ответ из чата — вставка в UI (основной путь) или авто-чтение буфера (опция).
- Парсинг «полных файлов с путями» по настраиваемому формату; расширяемо под diff / search-replace.
- **Предпросмотр** списка распознанных файлов; diff — **опциональный режим**; dry-run доступен.
- Применение: несуществующий файл → создать папки+файл с предупреждением; существующий → применять поверх; файлы вне отправленного контекста → разрешать.
- **Бэкап** изменённых файлов по умолчанию (`.ctxpack/backups/<timestamp>/`), отключаемо (тогда полагаемся на git); undo.
- **Песочница:** запись только внутри корня проекта; отключаемо в настройках. Жёсткий отказ от `..`/абсолютных путей при включённой песочнице.
- Кодировки/переводы строк — как в оригинале.
- **Автофикс невалидного ответа** (без ИИ): достроить закрывающие маркеры, найти висящий путь, отсечь мусор до/после полезного блока, подсветить место обрыва; ничего не применять без подтверждения.
- Предупреждение, если в репозитории есть незакоммиченные изменения.

## 6. Нефункциональные требования

- **Производительность:** обход + `.gitignore` + упаковка 3–4 МБ — целевой бюджет < 1 сек; параллельный обход (`ignore`/ripgrep-совместимый движок), потоковая запись в буфер.
- **Безопасность:** секреты и песочница по умолчанию; предупреждения в UI; отключение только явно.
- **Надёжность:** бэкапы + undo; атомарная запись (temp + rename); валидация путей; не падать на битых ответах.
- **Кроссплатформенность:** Windows (приоритет), macOS, Linux на едином абстрактном слое ОС.
- **Открытый исходный код** (лицензия — на выбор, например MIT/Apache-2.0), публичный репозиторий, CI-сборки под 3 ОС.
- **Дистрибуция:** установщик + **автообновление** + **самоинсталляция** (self-install) с проверкой подписи/хэшей.
- **Конфигурация:** JSON. Глобальные настройки + пресеты; пресет может лежать в корне проекта (шаринг через git); импорт/экспорт пресета файлом.

## 7. Ограничения и допущения

- Нет встроенного ИИ и сетевых вызовов к моделям.
- Оценка токенов не реализуется; производительность измеряется в МБ.
- Реальная вставка в браузер на объёмах ~МБ может тормозить на стороне чата — вне зоны ответственности приложения, но фиксируется как риск.
- Модуль B — второй этап; контракты (парсер, применение) закладываются в архитектуру с самого начала.

## 8. Архитектурные намётки (Rust + GPUI)

**Слои / crates (workspace):**

- `core` — модели (`Project`, `FileEntry`, `Preset`, `Rules`, `PackResult`), обход дерева (`ignore`), фильтрация, шаблонизатор вывода.
- `config` — `serde` + `serde_json`, схема настроек и пресетов, миграции версий.
- `clipboard` — `arboard` (plain + опц. HTML), потоковая запись.
- `apply` (этап 2) — парсер ответа (state machine / `nom`), `similar` для diff, backup/undo, песочница путей.
- `shell_integration` — трейт `ShellBackend` + бэкенды: `windows` (реестр), `macos` (Services/Finder Sync), `linux` (desktop actions).
- `ipc` — single-instance + передача путей (`interprocess`/named pipes/UDS).
- `updater` — автообновление и самоинсталляция (`self_update`-подобный механизм + подпись).
- `app` — GPUI UI (окно, дерево, редактор правил, предпросмотр, вкладка «Применить»), состояние (`gpui`/`gpui-component`-модели).
- `platform` — тонкий нативный хелпер/установщик shell-интеграции.

**Поток данных A:** путь(и) из ОС/UI → `core::scan(root, rules)` (параллельно, с `.gitignore`) → `core::pack(entries, template)` → `clipboard::write` + размер в UI.

**Поток данных B:** текст из UI/буфера → `apply::parse(template)` → `Vec<ParsedFile>` → (опц.) `diff` → `apply::commit(sandbox, backups)`.

## 9. Риски и открытые вопросы

1. **Производительность вставки в браузер** на 3–4 МБ — проверить на AI Studio; при проблемах — режим «частями» (несколько буферов/сегментов).
2. **МультиОС shell-интеграция** — разный объём работ; Windows через реестр проще, macOS Finder Sync требует подписи/entitlements.
3. **Формат ответа ИИ** может меняться — нужен расширяемый парсер и понятные ошибки; «автофикс» ограничен детерминированными правилами.
4. **Секреты**: ложные срабатывания/пропуски — вынести шаблоны в настройки, логировать, что скрыто.
5. **GPUI** — молодой фреймворк; заложить изоляцию UI от `core`, чтобы при необходимости сменить GUI.
6. Лицензия и правила репозитория (contributing, CI) — уточнить.
7. Пороговые значения (глубина, число файлов, «крупный файл») — вынести в настройки с дефолтами.

## 10. Дорожная карта

- **MVP (этап 1):** модуль A целиком (обход+gitignore, пресеты/правила, шаблон, предпросмотр+размер, копирование), UI на GPUI, JSON-конфиг, глобальный хоткей, базовая интеграция с Проводником (Windows), установщик.
- **Этап 2:** модуль B (парсер, предпросмотр/diff, применение, бэкап/undo, песочница, автофикс), авто-чтение буфера.
- **Этап 3:** shell-интеграция macOS/Linux, автообновление + самоинсталляция, импорт/экспорт пресетов, полировка UX.
