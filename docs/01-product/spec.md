# Техническая спецификация (Product Specification)

## 1. Суть и цель продукта
**CodeContext** создаётся для разработчиков, которые работают с бесплатными веб-чатами ИИ (Google AI Studio, ChatGPT, Claude, DeepSeek и др.) с большими контекстными окнами (1M+ токенов) без привязки к платным API.

Приложение решает две ключевые задачи:
1. **Модуль A (Context Packing):** мгновенно отобрать тысячи файлов кодовой базы по гибким правилам, отформатировать по шаблону и скопировать в системный буфер обмена.
2. **Модуль B (Change Applying):** принять текстовый ответ из веб-чата, детерминированно распарсить его (даже если ответ оборван), показать предпросмотр/diff и безопасно применить изменения к файлам проекта с возможностью отката (Undo).

> **Ключевой принцип:** Никакого встроенного ИИ и сетевых вызовов к LLM — только детерминированная, предсказуемая и молниеносная обработка текста.

---

## 2. Измеримые критерии успеха
1. **Скорость (< 1 сек):** Кодовая база объёмом ~1M токенов (≈ 3–4 МБ исходного текста, до 50 000 файлов) обходится, фильтруется и копируется в буфер обмена быстрее **1 секунды**.
2. **Эргономика (1–2 клика):** Запуск упаковки возможен прямо из контекстного меню Проводника Windows / Finder macOS / файловых менеджеров Linux или по глобальному хоткею.
3. **Нулевая утечка секретов:** Ни один файл секретов (`.env*`, `*.pem`, `id_rsa*` и др.) или тяжёлый артефакт сборки не попадает в буфер без явного разрешения пользователя.
4. **Абсолютная сохранность данных:** Применение ответа ИИ выполняется транзакционно (через бэкапы `.ctxpack/backups/<timestamp>/` и атомарную перезапись) и строго внутри песочницы корня проекта.

## 3. Функциональные требования

### 3.1. Модуль A — Упаковка контекста (`packing`)
* **Отбор файлов:**
  * Полная поддержка иерархических `.gitignore` (включая вложенные).
  * Настраиваемые пресеты правил `include` / `exclude` на базе `glob`-выражений.
  * Автоматическое игнорирование тяжёлых директорий (`node_modules`, `target`, `.git`, `dist`, `build`) с возможностью ручного включения.
  * Перехват секретов (`SecretGuard`) по умолчанию с выводом предупреждения в UI.
  * Эвристическое исключение бинарных файлов (проверка первых байт на `NUL` + список расширений).
  * Защита от циклических симлинков и предупреждение при аномалиях обхода (глубина > 32 уровней или > 50 000 файлов).
* **Форматирование и вывод:**
  * Настраиваемый шаблон (`OutputTemplate`): шапка (опциональное ASCII-дерево файлов), разделители, маркеры начала/конца файла, подвал.
  * Опциональная минификация кода (удаление комментариев и пустых строк без изменения логики).
  * Строгое сохранение оригинальных переводов строк (`LF` / `CRLF`).
  * Поддержка разбивки итогового текста на части (`PackChunk`), если объём превышает лимит вставки браузера.

### 3.2. Модуль B — Применение изменений (`applying`)
* **Парсинг и автофикс:**
  * Извлечение файлов из ответа ИИ по маркерам шаблона, блокам Markdown, блокам `SEARCH / REPLACE` или `Unified Diff`.
  * Детерминированный **Автофикс** битых ответов: отсечение преамбулы чата, восстановление висящих заголовков путей, автозакрытие оборванных блоков кода с пометкой `TruncatedWarning`.
* **Безопасность и транзакционность:**
  * **Песочница (`Sandbox`):** блокировка любых попыток записи за пределы корня проекта (`../`, абсолютные пути, диски Windows `C:\`, потоки NTFS ADS).
  * Проверка `git status` перед записью (предупреждение о незакоммиченных изменениях в репозитории).
  * Автоматическое создание снимка изменяемых файлов в `.ctxpack/backups/<timestamp>/` с `manifest.json` для мгновенного отката (**Undo**).

## 4. Нефункциональные требования и ограничения
* **Платформы:** Windows (приоритет №1), macOS, Linux.
* **Стек:** Rust (Edition 2024), GUI-фреймворк `gpui` + `gpui-component`.
* **Хранение конфигурации:** Человекочитаемый JSON (глобальные настройки в системном профиле + локальный `.ctxpack.json` в корне проекта для шаринга через Git).
* **Качество кода:** Запрет `unsafe`, `.unwrap()`, `.expect()`, `panic!()` и `std::env::set_current_dir` в боевом коде на уровне компилятора и Clippy.
