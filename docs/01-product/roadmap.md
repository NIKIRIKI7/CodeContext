## ФАЗА 1: Стабилизация, критические хотфиксы и брендинг (v0.1.1 — v0.1.2)

### Задача [8]: Устранение бага вызова из терминала (зависание, аномальный жор RAM, незапуск GUI)

- **Диагностика бага в текущем коде:**
  1. **IPC Deadlock:** В `crates/platform/src/lifecycle/ipc.rs` функция `try_connect_and_send_frame` при вызове из терминала пытается подключиться к именованному каналу/Unix-сокету. При наличии «зомби»-процесса или обрыва потока блокирующий `Stream::connect` или `read_exact(&mut ack)` может зависать на бесконечном ожидании.
  2. **Жадное сканирование корня:** В `crates/app/src/cli.rs` вызов без аргументов берёт `std::env::current_dir()`. Если запустить `codecontext` из домашней папки (`C:\Users\Username` или `~`), конструктор `ContextPackerState::new` синхронно запускает `index_project`, пытаясь обойти весь диск, сжирая гигабайты памяти на миллионах файлов.
- **Архитектурное решение:**
  - Добавить таймаут подключения к сокету IPC (не более 150 мс) с fallback на восстановление сервера.
  - **Lazy Scanning:** Отвязать открытие окна от чтения ФС. Сделать первый скан фоновым и асинхронным (`cx.spawn()`), с индикатором прогресса.
  - Добавить предохранитель в `cli.rs`: если `current_dir` совпадает с корнем диска (`/`, `C:\`) или домашней папкой (`~`), запрашивать явный выбор проекта вместо автосканирования.
- **Затронутые крейты:** `crates/app`, `crates/platform`, `crates/ui`.

### Задача [5]: Исправление сборки под openSUSE (CI / Linux distros)

- **Причина бага:** В openSUSE Tumbleweed/Leap системные библиотеки X11/Wayland и шрифтов называются иначе, чем в Debian/Fedora. В `.github/workflows/ci.yml` шаг `zypper` падал из-за отсутствия пакетов `lld`, `libX11-devel`, `libxkbcommon-x11-devel`.
- **Архитектурное решение:**
  - В `.github/workflows/ci.yml` скорректировать установку пакетов для `opensuse/tumbleweed`:
    ```bash
    zypper --non-interactive install gcc gcc-c++ binutils llvm-lld make curl ca-certificates pkg-config git \
      libX11-devel libXcursor-devel libXi-devel libxkbcommon-devel libxkbcommon-x11-devel wayland-devel \
      vulkan-devel fontconfig-devel freetype2-devel
    ```
  - Проверить совместимость скриптов сборки с префиксами `pkg-config` в контейнере `opensuse`.
- **Затронутые файлы:** `.github/workflows/ci.yml`, `.github/workflows/release.yml`.

### Задача [9]: Устранение UI-багов GPUI

- **Список исправлений:**
  - **Focus Trap:** Корректный перехват фокуса ввода: ввод текста в строке поиска дерева файлов не должен триггерить глобальные горячие клавиши (например, букву `C` как копирование).
  - **Backdrop Click Leak:** Клик по темному фону (`backdrop`) в модальных окнах метаданных и настроек должен закрывать окно, не пропуская клик сквозь слои к дереву файлов.
  - **SplitPane Limits:** Защита от схлопывания разделителя панелей при минимальных размерах окна (< 920px).
- **Затронутые крейты:** `crates/ui` (`shared/containers/split_pane.rs`, `features/main_window/view.rs`).

### Задача [11]: Фирменная иконка приложения

- **Архитектурное решение:**
  - Создать мастер-ассет иконки `assets/icons/app-icon.svg` (минималистичный куб с символом контекста `{…}`).
  - Сгенерировать артефакты платформ:
    - **Windows:** `assets/icons/app.ico` (мульти-разрешение: 16, 24, 32, 48, 64, 128, 256 px). Подключить через `.rc` скрипт и `embed-resource` в `crates/app/Cargo.toml`.
    - **macOS:** `assets/icons/app.icns` для `CodeContext.app/Contents/Resources`.
    - **Linux:** `assets/icons/hicolor/` (размеры 16x16 ... 512x512) для путей `/usr/share/icons/hicolor/`.
  - Отображать иконку в заголовке главного окна GPUI и в каскадном меню Проводника (значение `Icon` в реестре).
- **Затронутые крейты:** `crates/app`, `crates/platform`, `crates/ui`.

## ФАЗА 2: Фильтрация, расширенные пресеты и системные промпты (v0.2.0)

### Задача [1]: Выбор конкретных расширений и регулярные выражения (Regex)

- **Суть:** Возможность в один клик выбрать только `*.rs`, `*.ts`, `*.py` или задать регулярное выражение (например, `^crates/core/.*_service\.rs$`).
- **Архитектура решения:**
  - В `crates/core/src/preset/models/preset.rs` расширить агрегат `Preset`:
    ```rust
    pub struct Preset {
        // ... существующие поля
        pub include_extensions: Vec<String>, // Whitelist: ["rs", "toml"]
        pub exclude_extensions: Vec<String>, // Blacklist
        pub include_regex: Option<String>,   // Произвольный regex по rel_path
        pub exclude_regex: Option<String>,
    }
    ```
  - В `crates/scanner/src/discovery/parallel_walker.rs` внедрить быструю фильтрацию:
    1. **Стадия 0 (0 аллокаций):** Проверка расширения по расширенному набору без создания строк.
    2. **Стадия 1 (Regex):** Компиляция `regex::Regex` один раз перед обходом и проверка `regex.is_match(&rel_path)`.
  - В `crates/ui/src/features/context_packer/` добавить плашку быстрых фильтров расширений в тулбаре над деревом файлов (чипсы: `[rs]`, `[ts]`, `[py]`, `[+] Custom Ext`, `[.*] Regex`).
- **Затронутые крейты:** `crates/core`, `crates/config`, `crates/scanner`, `crates/ui`.

### Задача [12]: Глубокие конфигурационные пресеты в JSON (Schema v2)

- **Суть:** Расширенный формат `.ctxpack.json` и глобального `config.json` с тонкой настройкой по папкам.
- **Спецификация схемы Schema v2:**
  ```json
  {
    "schema_version": 2,
    "name": "Backend-Only",
    "base_preset": "Default",
    "respect_gitignore": true,
    "minify_code": false,
    "filters": {
      "include_extensions": ["rs", "toml"],
      "exclude_extensions": ["lock", "log"],
      "include_regex": "^crates/(core|apply)/",
      "folder_overrides": {
        "crates/ui": "exclude",
        "tests/fixtures": "include"
      }
    },
    "template": {
      "include_file_tree": true,
      "max_chunk_bytes": 1048576
    }
  }
  ```
- **Миграция:** В `crates/config/src/schema/migration.rs` реализовать конвейер `migrate_v1_to_v2`, переводящий старые плоские `include_globs` в блок `filters`.
- **Затронутые крейты:** `crates/config`, `crates/core`.

### Задача [2]: Системный промпт для ИИ-чатов и инструкция для парсера

- **Суть:** Веб-чаты дают лучший результат, если в начале контекста явно указать системные инструкции: как оформлять патчи (Search/Replace или Canonical), не вставлять преамбулу и не обрывать код.
- **Архитектура решения:**
  - В `core::preset::models::template::OutputTemplate` добавить поле:
    ```rust
    pub system_prompt_preset: SystemPromptMode,
    ```
    с вариантами:
    - `None` — сырой контекст;
    - `CanonicalFullFiles` — инструкция по формату `=== FILE: ... ===`;
    - `SearchReplacePatch` — инструкция отдавать блоки `<<<<<<< SEARCH ... >>>>>>> REPLACE`;
    - `UnifiedDiffPatch` — инструкция выдавать стандартный `git diff`.
  - В UI Context Packer добавить кнопку-переключатель: _"Копировать с системным промптом (для GPT/Claude/Gemini)"_.
- **Затронутые крейты:** `crates/core`, `crates/ui`.

## ФАЗА 3: Файловые операции, точечный эдитор и терминальный раннер (v0.2.5)

### Задача [6]: Переименование папок и файлов

- **Суть:** Возможность переименовывать элементы кодовой базы как вручную в UI, так и автоматически при получении директивы от ИИ.
- **Архитектура решения:**
  - **В Модуле B (Applying):**
    - Поддержка директив ИИ: `=== RENAME FILE: old/path.rs -> new/path.rs ===` или `=== MOVE: ... ===`.
    - В `core::applying::aggregates::apply_plan::FileOperation` добавить вариант:
      ```rust
      RenameFile { old_path: String, new_path: String }
      ```
    - `Sandbox` проверяет оба пути на запрет выхода из корня.
    - В `backup_manifest` пишется операция переноса для гарантированного отката по кнопке **Undo**.
  - **В Модуле A (Context Packer):**
    - ПКМ по строке дерева файлов -> пункт `Rename` -> инлайн-инпут или модальное окно с переименованием на диске через `std::fs::rename`.
- **Затронутые крейты:** `crates/core`, `crates/apply`, `crates/ui`.

### Задача [3]: Точечное редактирование файлов в UI и моментальное сохранение

- **Суть:** Возможность прямо в окне предпросмотра/diff точечно отредактировать строки кода перед записью или сохранить отдельный файл, не дожидаясь применения всего плана.
- **Архитектура решения:**
  - В `crates/ui/src/features/change_applier/components/diff_view.rs`:
    - Добавить тулбар отдельного файла: кнопка `Применить только этот файл` (Apply File) и `Редактировать вручную` (Edit).
  - Режим редактирования переключает `VirtualTextView` в режим интерактивного редактора с вызовом `apply_operation_to_text`.
  - Мгновенное сохранение использует `crates/apply/src/storage/atomic_writer.rs` с сохранением одиночного бэкапа в `.ctxpack/backups/`.
- **Затронутые крейты:** `crates/apply`, `crates/ui`.

### Задача [7]: Фоновый запуск терминальных команд (PowerShell / Bash) после применения патча

- **Суть:** После применения кода от ИИ запустить сопутствующие команды (например, `cargo check`, `npm test`, `git status`).
- **КРИТИЧЕСКИ ВАЖНО (Безопасность):** Автоматическое выполнение команд от ИИ — прямой вектор Remote Code Execution (RCE через prompt injection).
- **Безопасная архитектура:**
  1. **Парсер директив:** Распознавание блока `=== RUN: cargo test ===` или ` ```sh ... `.
  2. **Zero-Trust диалог подтверждения:** Команда **никогда не запускается вслепую**. В UI появляется предупреждающий блок:
     _«ИИ предлагает выполнить команду: `cargo test`. Запустить?»_ с кнопками `Запустить`, `Редактировать`, `Отклонить`.
  3. **Runner-адаптер (`crates/platform/src/shell/runner.rs`):**
     - Windows: `powershell.exe -NoProfile -NonInteractive -Command ...`
     - Linux/macOS: `$SHELL -c ...` или `/bin/sh -c ...`
     - Запуск через `std::process::Command` в фоновом потоке с перехватом stdout/stderr в неблокирующий кольцевой буфер и выводом в нижнюю консольную шторку UI.
- **Затронутые крейты:** `crates/core` (`system::ports`), `crates/platform`, `crates/ui`.

### Задача [13]: Поэтапная и наглядная очистка (Clean / Purge)

- **Суть:** Управление дисковым пространством и системным мусором.
- **Архитектура решения:**
  - Реализовать службу очистки `HousekeepingService` с разбивкой на независимые категории:
    1. **История бэкапов (`.ctxpack/backups/`):** подсчёт размера папок снимков, удаление старых снимков старше $N$ дней или оставление последних $K$ штук.
    2. **Временные файлы (`.*.tmp`):** поиск и зачистка брошенных atomic-файлов после аварийных завершений.
    3. **IPC и сокеты:** удаление осиротевших сокетов в `%TEMP%` / `/tmp`.
    4. **Интеграция с ОС (Shell Unregister):** полная очистка ключей реестра Windows / XDG desktop файлов / macOS Workflows.
  - В UI добавить раздел в окне настроек: **«Очистка и обслуживание»** с визуальным расчётом освобождаемого места по каждой категории и кнопкой «Очистить выбранное».
  - Добавить CLI-команду: `codecontext --clean [all|backups|tmp]`.
- **Затронутые крейты:** `crates/core`, `crates/apply`, `crates/platform`, `crates/ui`, `crates/app`.

## ФАЗА 4: Дистрибуция, инсталлятор и расширяемость (v0.3.0+)

### Задача [10]: Полноценный установщик (Wizard) и деинсталлятор

- **Суть:** Автономный установщик, который скачивает/распаковывает нужный релизный бинарник с GitHub под архитектуру пользователя, позволяет выбрать путь и настраивает систему.
- **Архитектура решения:**
  - Разработать автономный легковесный инсталлятор `codecontext-setup` (или режим запуска `codecontext --setup`):
    - Определение платформы: `x86_64` или `aarch64`.
    - Выбор режима:
      - **Per-User (без прав админа):** `%LOCALAPPDATA%\Programs\CodeContext` (Windows), `~/.local/bin` (Linux), `~/Applications` (macOS).
      - **Custom Directory:** Пользователь сам выбирает папку через диалог `PathPromptOptions`.
    - Копирование бинарника, создание ярлыка в меню «Пуск» / Desktop Entry.
    - Регистрация контекстного меню проводника через встроенный порт `ShellIntegrationPort`.
    - Запись метаданных деинсталлятора: `uninstall.exe` / `codecontext --uninstall`, который удаляет бинарник, ярлыки, контекстное меню и чистит сокеты.
- **Затронутые крейты:** `crates/app`, `crates/platform`.

### Задача [4]: Модуль плагинов (Plugin Architecture)

- **Концепция:** Позволить сторонним разработчикам создавать расширения: кастомные парсеры экзотических LLM-форматов, фильтры секретов под корпоративные хранилища (Vault, 1Password) и интеграции с кастомными редакторами.
- **Архитектурный выбор (Безопасность + Скорость):**
  - **Этап 4.1 (External CLI / JSON-RPC Hooks):** Самый быстрый старт без утяжеления зависимостей. Приложение ищет плагины в `~/.config/CodeContext/plugins/` и общается с ними через stdin/stdout по JSON-RPC протоколу.
  - **Этап 4.2 (WebAssembly / WASI Sandbox):** Интеграция легковесного Wasm-рантайма (например, `wasmtime` или `extism`) в отдельный адаптер `crates/plugins`. Плагин представляет собой `.wasm` файл, работающий в строгой песочнице памяти с нулевым риском уронить основное приложение.
- **Затронутые крейты:** новый крейт `crates/plugins`, `crates/di`, `crates/core`.

## Инженерные инварианты при реализации

1. **Контроль аллокаций (`dhat`):** Добавление фильтрации по расширениям и regex (Задача 1) не должно нарушать инвариант 1 аллокации кучи в тесте `crates/scanner/tests/heap_allocations.rs`.
2. **Архитектурный линтер (`architecture.rs`):** Модуль плагинов и терминальный раннер должны оставаться за строгими портами `core` и собираться в инфраструктурных адаптерах. В `core` запрещено тянуть зависимости рантаймов.
3. **Безопасность (Sandbox):** Переименование файлов (Задача 6) и запуск команд (Задача 7) должны блокировать любые относительные пути с `..` и требовать явного подтверждения пользователя.
