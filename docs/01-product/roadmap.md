# Дорожная карта (Roadmap) и Матрица рисков

## 1. Этапы развития проекта

### Этап 1: MVP (Ядро упаковки + UI + Базовая интеграция с Windows)

- [x] Архитектурный каркас воркспейса (8 крейтов) и фитнес-тесты `architecture.rs`.
- [x] Бенчмарки пропускной способности (`divan`) и контроль 1 аллокации кучи (`dhat`).
- [x] Реализация поддомена `packing` (параллельный обход `ignore`, `SecretGuard`, детектор бинарников).
- [x] Каскадный загрузчик конфигурации (`config`: Global JSON + локальный `.ctxpack.json`).
- [x] Главное окно на `gpui`: виртуализированное дерево с чекбоксами, редактор пресетов, `Live Preview`.
- [x] Режим `headless` и регистрация в контекстном меню Проводника Windows (через реестр HKCU).
- [x] Глобальный хоткей и Single-Instance IPC.

### Этап 2: Модуль применения изменений (`applying`)

- [x] Расширяемый парсер ответов ИИ (`fenced_blocks`, `search_replace`, `unified_diff`).
- [x] Детерминированный движок `autofix` для восстановления оборванных ответов чата.
- [x] Вкладка «Применить» в UI с просмотром списка файлов и подсветкой изменений (`diff_view`).
- [x] Песочница путей (`sandbox`), проверка `git_status`, транзакционная запись (`atomic_writer`) и бэкапы с Undo (`backup_drawer`).

### Этап 3: Кроссплатформенная полировка и Дистрибуция

- [x] Интеграция с оболочками macOS (Finder Sync / Services) и Linux (`.desktop` actions для Nautilus/Dolphin).
- [x] Режим сегментированного копирования (`chunker`) для обхода зависаний браузера на объёмах > 3 МБ.
- [x] Автообновление и самоинсталляция (`updater`) с проверкой криптографической подписи и SHA-256.
- [x] Локализация интерфейса (`fluent-templates`, RU / EN).

## 2. Матрица технических рисков и способы их минимизации

|  №  | Риск                                                                                   | Вероятность |   Влияние   | Архитектурное решение (Митигация)                                                                                                                            |
| :-: | :------------------------------------------------------------------------------------- | :---------: | :---------: | :----------------------------------------------------------------------------------------------------------------------------------------------------------- |
|  1  | **Зависание вкладки браузера** при вставке 3–4 МБ текста в поле ввода чата             |   Высокая   |   Среднее   | В `core::packing` заложен сервис `chunker.rs` и модель `PackChunk`, позволяющие разбивать вывод на сегменты по $N$ МБ без разрыва файлов.                    |
|  2  | **Лаги UI (GPUI)** при отрисовке дерева из 50 000 файлов и предпросмотре 4 МБ текста   |   Средняя   |   Высокое   | Дерево хранится в плоском массиве (`FlatTreeNode`), а компонент `virtual_text.rs` рендерит только видимые 60–80 строк по смещениям `line_offsets` за $O(1)$. |
|  3  | **Нестабильный формат ответа ИИ** (разные маркеры, мусор в начале, обрыв на полуслове) |   Высокая   |   Высокое   | Цепочка парсеров в `crates/apply/src/parsing/` + детерминированный `autofix.rs` + обязательный предпросмотр с баннером `TruncatedWarning`.                   |
|  4  | **Изменения API в молодом фреймворке GPUI**                                            |   Средняя   |   Среднее   | Полная изоляция `gpui` внутри `crates/ui` и `crates/di` (защищено `deny.toml` и `architecture.rs`). Доменное ядро `core` не зависит от UI.                   |
|  5  | **Потеря данных при сбое питания или ошибке доступа** во время применения патча        |   Низкая    | Критическое | Паттерн _Unit of Work_ (`transaction.rs`): запись во временные файлы + `sync_all` + атомарный `rename` + `manifest.json` в папке бэкапа.                     |
