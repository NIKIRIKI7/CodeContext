# Пользовательские сценарии и приёмочные критерии

В соответствии с практиками DDD (Глава 2, *Learning Domain-Driven Design*), поведение системы фиксируется на Едином Языке (Ubiquitous Language) через сценарии использования и поведенческие спецификации в формате Gherkin.

---

## Модуль A: Упаковка контекста

### Сценарий A1: Мгновенная упаковка из Проводника (Headless Fast-Path)
**Роль:** Разработчик.
**Цель:** Скопировать контекст проекта в буфер обмена за 1 клик без открытия главного окна.

```gherkin
Scenario: Быстрое копирование проекта из контекстного меню ОС
  Given в папке проекта "/workspace/my-app" лежит профиль ".ctxpack.json"
  And в папке присутствует файл секретов ".env.production"
  When разработчик нажимает ПКМ по папке и выбирает "CodeContext: Copy"
  Then приложение запускается в режиме "Headless"
  And обходит файлы с учётом ".gitignore" и правил профиля менее чем за 1 секунду
  And исключает файл ".env.production" согласно защите "SecretGuard"
  And записывает упакованный контекст в системный буфер обмена
```

### Сценарий A2: Тонкая настройка отбора и живой предпросмотр в UI
**Роль:** Разработчик.
**Цель:** Визуально выбрать нужные подпапки/файлы, проверить размер контекста и скопировать результат.

```gherkin
Scenario: Интерактивный отбор файлов через дерево проекта
  Given разработчик открыл проект в главном окне CodeContext
  When он снимает чекбокс с директории "crates/ui" в дереве файлов
  Then итоговый размер контекста в МБ пересчитывается мгновенно (< 16 мс) без повторного чтения диска
  And в панели "Live Preview" отображаются только выбранные файлы
  And при нажатии кнопки "Копировать" буфер обмена получает актуальный текст
```

### Сценарий A3: Каскадные пресеты и защита от небезопасных локальных конфигов
**Роль:** Разработчик в команде.
**Цель:** Использовать общий `.ctxpack.json` из Git-репозитория, не рискуя случайно отправить свои локальные ключи.

```gherkin
Scenario: Защита глобальных правил секретов при загрузке проектного пресета
  Given разработчик клонировал чужой репозиторий с файлом ".ctxpack.json"
  And в ".ctxpack.json" добавлено правило принудительного включения ".env"
  When CodeContext загружает каскадную конфигурацию проекта
  Then глобальный фильтр "SecretGuard" блокирует автоматическое включение ".env"
  And в интерфейсе появляется баннер предупреждения о скрытых секретах
```

## Модуль B: Применение изменений

### Сценарий B1: Безопасное применение валидного ответа ИИ с созданием бэкапа
**Роль:** Разработчик.
**Цель:** Применить сгенерированные в веб-чате изменения к файлам проекта с возможностью отката.

```gherkin
Scenario: Транзакционное применение плана изменений
  Given разработчик скопировал ответ из чата ИИ и открыл вкладку "Применить"
  When парсер распознаёт 5 изменённых и 1 новый файл
  And разработчик проверяет построчный diff и нажимает "Применить изменения"
  Then система проверяет все пути через "Sandbox" на отсутствие выхода за корень проекта
  And сохраняет оригиналы 5 файлов и "manifest.json" в ".ctxpack/backups/<timestamp>/"
  And атомарно записывает новые версии файлов на диск
```

### Сценарий B2: Детерминированный Автофикс оборванного ответа ИИ
**Роль:** Разработчик.
**Цель:** Восстановить ответ ИИ, который оборвался на середине файла из-за лимита выходных токенов чата.

```gherkin
Scenario: Автовосстановление незакрытого блока кода
  Given вставленный ответ ИИ содержит текстовую преамбулу и незакрытый блок файла "src/lib.rs"
  When парсер обнаруживает аномалию "UnclosedFileBlock"
  And разработчик нажимает кнопку "Автофикс"
  Then система отсекает разговорную преамбулу до первого маркера пути
  And достраивает закрывающий маркер для "src/lib.rs"
  And помечает файл статусом "TruncatedWarning" с подсветкой места обрыва в окне diff
  And ожидает явного подтверждения пользователя перед записью на диск
```
